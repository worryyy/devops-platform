# P6 · 链路与巡检

> **目标**：OTel 埋点 + Jaeger 打通慢接口排障闭环（慢接口页 → span →
  日志）；巡检引擎上线首批检查器并自动出报告。
> **工期**：3 周（前半链路、后半巡检，可拆）。
> **前置依赖**：P1 验收 A1（集群）、P4 验收 A1（trace_id 查日志依赖）。
> 跨仓库提示：OTel 埋点改业务源码仓 `app-test`（13 个 Go 服务）。
> **蓝图引用**：§7.3 链路（Jaeger 起步、CH 自研页为可选演进）、§7.4 巡检。
> **状态**：⬜ 未开始

## 1. 任务清单

### 1.1 链路（第 1-1.5 周）
- [ ] `k3s/helm-values/platform/otel-collector.yaml`：otel-collector
      deployment（~300M，nodeSelector worker），OTLP 接收 → 导出
      Jaeger；统一采样头（后续服务侧 `OTEL_TRACES_SAMPLER=parentbased_traceidratio`，
      常态 10%，压测窗口 100%）
- [ ] `k3s/helm-values/platform/jaeger.yaml`：jaeger all-in-one
      （~512M-1G，nodeSelector worker，storage=memory/badger PVC 10G，
      ingress className nginx + host）
- [ ] 业务仓 `app-test`：13 服务引入 `otelgin`（HTTP）与按需
      `otelgrpc`；`trace_id` 注入 slog 日志字段与响应头 `X-Trace-Id`；
      环境变量经 go-service chart `api.env` 机制注入
      （`OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector.platform.svc:4318`、
      `OTEL_SERVICE_NAME=<service>`）——chart 侧在 values 默认开
- [ ] 平台慢接口页：
  - 数据源 v1：Jaeger Query API（`/api/traces?service=&operation=&
    lookback=1h`）+ Prometheus `ecampus:http_request_duration_seconds:
    p95:5m` TopN 定位
  - `GET /api/traces?service=&slow=true&limit=20` → 平台后端代理
    Jaeger API，返回 trace 摘要（根 span/耗时/pod）
  - `GET /api/traces/:id` → span 树（折叠 json，前端树形渲染）
  - 前端 `/traces` 页：服务选择 + TopN 慢接口列表 → 点开 span 树 →
    「查日志」按钮跳 `/logs?trace_id=`（闭环完成）
- [ ] （可选演进，时间富余才做）span 入 CH：collector 加 clickhouse
      exporter → `spans` 表 → 平台自研聚合页；不做则 Jaeger 页够用
- [ ] pprof 排障链最后一环：go-service chart 统一约定 pprof debug 端口
      （业务仓 `import _ "net/http/pprof"`，chart values 增加容器端口
      6060，**不进 ingress**）；NetworkPolicy 仅放行平台/monitoring 来源
      访问该端口；排障路径 = 慢接口页定位到服务 → 平台一键抓取
      `debug/pprof/profile?seconds=30`（后端代理，经 SA 网络可达）→
      返回 .pb.gz 供 `go tool pprof` 分析

### 1.2 巡检引擎（第 1.5-3 周）
- [ ] `migrations/008_inspections.sql`：
      `inspection_runs(id bigserial, check_name text, target text,
      status text CHECK IN(pass/warn/fail), detail jsonb, duration_ms int,
      started_at, created_at)` + 唯一索引 (check_name, target, started_at)
- [ ] `inspection/checks/*.yaml`：声明式巡检项（name/type/target/
  params/threshold/timeout/severity）；`internal/inspection/` 加载器
  + 校验（type 必须在已注册检查器集合内）
- [ ] 巡检执行器：
  - 调度：robfig/cron 全量周期（默认 06:00 逐日 + 手动）；worker 池
    并发 10，单检查器超时隔离（context deadline），失败重试 1 次
  - 结果幂等入库 + 与上次 run diff（`status 变化` 才进报告变化区）
- [ ] 首批检查器（internal/inspection/checkers/）：
  - `pg_dial`：TCP+`select 1`（复用 GORM 连接），连接池水位
    （`pg_stat_activity` count / max）
  - `redis_dial`：PING + `INFO memory` used_memory 阈值
  - `kafka_lag`：kafka exporter 指标 lag 求和阈值
  - `ch_ingest`：CH `system.parts` 健康 + logs 表近 10min 增量>0
    （P4 管道活性巡检）
  - `deploy_replicas`：k8s API 遍历 app ns Deployment
    availableReplicas==spec.replicas（in-cluster SA 只读，role 复用
    platform 的读权限，需在 release-rbac 外新增 platform-reader Role）
  - `ingress_config_drift`：app ns Ingress 数量与 GitOps 仓渲染数量
    比对（拉 gitops repo 渲染 yaml 计数）
  - `cert_expiry`：k8s TLS Secret 证书 notAfter <30d 告警
  - `disk_usage`：node_exporter 可用率 <20% warn/<10% fail
  - `backup_check`：MinIO `backups/` 前缀下 PG dump 文件
    存在性/大小/时间戳（依赖 P1 MinIO + 新增 PG dump cron job：
    `platform/server` 或独立 CronJob pg_dump → MinIO，每日 03:00）
- [ ] 巡检报告：`GET /api/inspections?date=&status=`、
  `POST /api/inspections/run`（admin 手动触发全量）；报告 HTML 入
  MinIO（`reports/inspection/YYYY-MM-DD/`），异常项（fail/warn 变化）
  飞书推送；前端 `/inspections` 页：检查项矩阵（最新状态）+ 历史
  趋势 + 报告深链
- [ ] 自动修复：本期不做（只报告不动手，白名单机制留 P7）

## 2. 验收标准
- [ ] A1 埋点在流：k6 流量下 Jaeger UI 有 13 服务的 trace（采样率
      生效：常态约 10%）；日志页能按 trace_id 查到同请求日志
  （X-Trace-Id 链路闭环）
- [ ] A2 慢接口页：`/traces` 列出 TopN 慢接口 → 点开 span 树能看到
      DB/RPC 子 span 耗时 →「查日志」跳转带 trace_id 过滤的日志页
- [ ] A3 巡检执行：手动触发全量 → inspection_runs 9 类检查器各产出
      记录；构造一个 fail（如停 fluent-bit 触发 ch_ingest）→ 飞书收到
      异常推送且报告 diff 只含变化项
- [ ] A4 备份检查：PG dump CronJob 凌晨跑 → MinIO 出现带日期 dump →
      backup_check pass；手动删掉 dump → 下轮巡检 fail（证明检查器
      真的在看）
- [ ] A5 周报接入：周报新增「巡检摘要」段（fail/warn 计数与 Top）
- [ ] A6 资源回归：`kubectl top nodes` —— jaeger+collector+巡检新增
      负载在 §3 预算内（node3 增量 <1.5G）

## 3. 交付结果
- **代码**：业务仓 OTel 接入 PR；chart env 注入默认值；internal/
  inspection（引擎+9 检查器）；traces API 与前端两页
- **部署物**：otel-collector/jaeger values+app；pg-dump CronJob；
  platform-reader Role
- **数据**：inspection_runs 流水、MinIO 巡检报告与 PG dump 归档
- **文档**：巡检项 YAML 字段说明 + 新增检查器指南（模板代码路径）

## 4. 风险与回退
| 风险 | 缓解 |
|---|---|
| 全量采样打爆 collector/CH | 采样率 env 热调（改 values 重启服务即可）；压测窗口限时开 100% |
| 业务仓发版窗口长 | 埋点随正常发布节奏灰度接入，不阻塞本阶段其他任务 |
| Jaeger all-inone 单点 | 定位为排障工具非审计系统，丢 trace 可接受（蓝图已定位） |
| 巡检误报噪音 | diff-only 报告 + 状态连续 N 轮才推飞书（参数进 checks yaml） |
