## 4. 风险与回退
| 风险 | 缓解 |
|---|---|
| grafana 镜像源与插件拉取 | 用 ACR 转存 grafana 镜像（沿用 postgresql 先例） |
| iframe 嵌入被 X-Frame-Options 拦 | grafana values 设 `allow_embedding: true` + 同域反代（已同域） |
| 周报数据源单点失败 | aggregate.py 各数据源独立 try/except，缺失段在报告标注缺口（蓝图 §7.1 降级原则） |
| 飞书限频 | 发送器带 429 退避重试；同卡片聚合多条告警（P5 再演进） |

关键实现取舍（与计划的偏差）：

- **飞书应用模式**：群机器人 webhook 改为用户提供的飞书应用凭据
  （`FEISHU_APP_ID/SECRET`，OpenAPI tenant_access_token + im/v1 卡片），
  webhook 模式保留为备选。凭据只进集群 Secret
  `platform-server-observability`（模板见 `k3s/secrets/`）。
- **deploy_context 落库**：计划文本「deploy-context receiver 保持空」与
  「只落库不通知」矛盾——receiver 增加 webhook_configs 指向平台（仍是
  唯一通道，无任何人类通知集成），由 alertgw 网关侧执行只落库不通知。
  test-observability.sh 断言同步收紧（仅 name+webhook_configs 两键）。
- **周报预览**：iframe 走 `/api/reports/:id/preview` API 代理流式返回，
  而非 MinIO 预签名直链（MinIO 无集群外入口；预签名 URL 另由
  `/api/reports/:id/url` 提供）。周报 Job 由 platform-server 内
  robfig/cron（周一 09:00 Asia/Shanghai）创建 `pulseops/report-runner`
  镜像 Job，RBAC 见 `k3s/ci/jenkins/platform-report-jobs.yaml`。
- **Grafana**：chart 9.0.0 vendored，镜像 12.1.3 经 ACR 转存（12.0.0 有
  file-provisioning `provisioning.check_sum` 回归）；嵌入走
  `serve_from_sub_path` + 平台 `/grafana` 反代（不 strip 前缀），服务端
  注入 grafana admin basic 凭据，浏览器零二跳。数据源地址为
  `http://prometheus-server.monitoring.svc`（计划文本的
  prometheus-monitoring.svc:9090 与实际 chart svc 名不符）。
- **Pod TopN 采集**：kubelet cadvisor job 的 metric_relabel keep 放开
  `container_cpu_usage_seconds_total|container_memory_working_set_bytes`。

**部署旁路说明**：当日集群 → GitHub 出网中断，Argo 无法同步；P3 组件经
`helm template` 本地渲染 + `kubectl apply` 直推（与 git 内容一致），

出网恢复后 Argo 自动接管，届时可重新开启 selfHeal（app 定义即 git
现状）。
